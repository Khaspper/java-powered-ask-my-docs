Ask my docs

About

I am learning Java because the jobs I want ask for Java and Spring... This is the project that I have built to learn it both... It's a simple RAG system basically it holds documents the user uploads and answers the query using only what those documents contain using whatever AI model you want... I WAS using gemini-embedding-2 for embeddings and gemini-3.7-flash for answering the users query... but I changed it so any AI model using the OPENAI SDK can be used right now I am using nomic-embed-text as the embedding model and llama3.2 for answering the users query... I was using Gemini I thought it would be a good idea (Nearly when I was done with the project) to just create an about page to dump what happened while I was building this project.

24 August — starting again

I came back and didn't write a feature I wrote a plan first

I have built an entire production RAG system in (TS and Python) by myself before so I knew the system pretty well... So with the help of AI I broke the whole app into a graph of nodes the smallest ones being the first ones to work on

Meaning

What I learned worked well was dividing these nodes to "pure function" like... This node is small enough if it only does one thing and the upper nodes can be built with the nodes underneath it... If that makes sense...

Every node got a line saying how I would know if the node was done for example a curl command a SQL query a log line... This is the single thing that made the rest of "building via nodes" easier because I never had to guess whether I was finished... I thought of it like a Test for each node

I also started writing down decisions in short files one per decision with the options I turned down just incase this bites me later down the project... Then I added Postgres and pgvector in Docker and the documents table...

26 August — Most of the work

Seven commits... Upload with a duplicate check, the list endpoint, cutting text into chunks, the chunks table, deleting a document along with its chunks, a chunk count on the list, then the first call to Gemini and the first embeddings coming back, then saving those numbers next to the chunk

The chunking is deliberately dumb... 1000 characters at a time each slice repeating the last 200 characters of the one before it so a sentence cut in half still has part of the previous sentence context... This project was for me to understand Java and SpringBoot not a RAG project

27 August — Chunk searching

That morning I turned the question into embeddings the same way ask Postgres for the closest chunks... Later that evening I built the answer generation... Hand the retrieved chunks to the model with one rule... Answer only from the text given otherwise reply back saying it doesn't know...

Then between 18:48 and 18:59 I had four commits:

  • 18:48Let failure happen and let reaper handle it
  • 18:52Get null embeddings with < tries
  • 18:54make AskmydocsApplication have a timer basically a cron
  • 18:59background job fills in chunks that never got their embedding

I purposely let failures happen... For this version for one failed call to Google threw away the entire upload. basically upload a 40 page PDF and if Google failed on chunk 31 of 96 you basically lose it all... I have PLAYED THESE GAMES BEFORE (Squid Games Season 2 Reference)... So I decided to build a reaper later

A chunk that fails is saved anyways with no embeddings and a counter bumped up by one and the upload still succeeds it just tells you 96 chunks 95 with embeddings... A reaper wakes up every sixty seconds grabs up to fifty chunks that have no embeddings and fewer than three attempts and tries again... Three retries and it leaves the chunk alone forever (I did not build anything to handle this)

The two options I turned thought of and just rejected are: fail the whole upload (one fail / blip throws the document) OR do no embedding during upload at all (fast uploads but nothing is searchable for up to a minute and the response cannot tell you whether anything worked)

What I left out

No reranking no rewriting your question before searching no mixing keyword search with number search... All three would give better answers... But I didn't want this project to get to big...
